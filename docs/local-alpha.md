# Local alpha contract

> Lifecycle: locked for implementation, 2026-09-09. Engineering choices under the owner’s instruction to build; broader first-release gates remain in SPEC.md.

The runtime was imported with source history into Continuum on runtimev1. Public Menagerie source cutover is gated on a public shared-runtime distribution (docs/menagerie-adapter.md). Menagerie migration is prepared separately; installed services and main branches are not cut over by these changes.

The first slice runs one daemon per private state directory: the modern authenticated HTTP adapter listens on a Unix socket inside that directory (`v1.sock`, versioned by name so an older client meets no socket rather than a contract it cannot speak; the contract itself is negotiated with the `version` operation and documented in [v1-contract.md](v1-contract.md)), and the legacy WebSocket adapter listens on a loopback TCP port; both drive the same process registry. The modern CLI can open a PTY, inspect sessions, page/stream recorded events, claim/renew/release/take over control, send input, resize, and stop. Observers never attach through the legacy takeover operation. Modern leases last 60 seconds; a fresh acquisition/takeover fences prior leases, including legacy token rotation. Authority is personal-host operator access in this alpha, not grants for untrusted users.

Use bbolt transactions with fsync enabled for host identity, operation intent/results, bounded event history and block metadata. This avoids a hand-written crash journal and CGO; SQLite remains a future query-driven option, not a prerequisite. Reference: https://pkg.go.dev/go.etcd.io/bbolt. Start with 16 MiB and 4096 retained events per host and up to 1024 recorded blocks; at the block cap the oldest exited or interrupted block is retired with its events, and resource_exhausted is returned only when every recorded block is active. The operation ledger holds at most 4096 intents: the oldest resolved identities are retired to make room, unresolved intents are never retired (only they can exhaust it), and a request naming a block with no live process never occupies it. These are logical retention limits; database allocation can be larger.

Each PTY block selects one recording policy at `open`: `none`, `visible`, `lines:N` (`1..10000`), or `full` (the default for old and new clients). `none` retains lifecycle records but no PTY payload. `visible` requires `screen-v1` and replaces its prior payload with one committed full-screen redraw and durable frame. `lines:N` keeps the trailing N newline-delimited output lines. `full` keeps the raw stream subject to the host-wide event and byte caps. Input bytes and control secrets are never recorded. All four policies transactionally advance the block's lifetime output-byte offset even when payload is discarded, so holder adoption neither duplicates nor replays deliberately unrecorded bytes after daemon restart. A selected policy that cannot be captured is reported as incomplete; an actual store write failure still degrades capture and fences later mutations.

A block's retained output can be written as an asciicast v3 stream with `continuum export --block ID` (a client-side read of the journal); a retention gap, explicit purge, or unclean-epoch history becomes an `m` marker event, never a silent time skip, and an incomplete export exits non-zero. `continuum purge --block ID` accepts exited blocks only and deletes output payload plus the durable visible frame while preserving block/lifecycle records, the policy, and the lifetime resume offset. `continuum retire --block ID` removes an exited block and all scoped state. Both operations conservatively refuse active or interrupted blocks whose process fate is not settled. Deleted bbolt pages remain allocated until `continuum compact`, which takes the database lock, refuses a running daemon, writes a validated private copy, and atomically replaces `state.db`. The first open by this build atomically upgrades on-disk schema 1 to schema 2 and stamps legacy blocks `full`; schema-1 binaries then refuse the database instead of silently ignoring privacy-sensitive policies. A binary rollback therefore also requires its matching state backup. Retention gaps and intentional purges are explicit. Events are committed before observers read them. Polling observers hold no long-lived transaction and cannot backpressure a process.

New captures use the explicit private state directory, not the installed Menagerie home. Metadata/history survive restart. PTY processes survive too: a per-block holder process (own session, owns the PTY master, reaps the child) keeps the block alive while the daemon is down, drains its output into a 256 KiB ring, and hands the master plus the ring to the next daemon over a private Unix socket under `<state>/holders/`. Startup adopts every held block (`adopted` event with `gap_bytes`/`dropped_bytes`), settles children that exited meanwhile (`exited` with the recorded code) and leaves blocks whose holder is gone marked interrupted. An unclean epoch marks retained history incomplete, including exited blocks, until those records are retired. New blocks start a new capture record. Legacy compatibility mode retains its existing configuration and tmux behavior. No adoption of live tmux sessions is performed by the modern mode.

Each mutation has a caller-supplied request ID, stored with a request digest before effects. Repeated IDs return the saved result; mismatched payloads conflict; unresolved intents return indeterminate after a crash, never silently repeat a launch. Token-bearing control results are not journaled; an uncertain acquire requires a new explicit takeover. Input completion confirms the write, not execution of the command.

Acceptance: same process observed by two clients without takeover; no-client output replay; explicit takeover fences old input including legacy attach; restart recovers records and re-adopts held processes with the same PID and an explicit adopted marker; duplicate/conflicting intents; bounded replay with gaps; database lock and incompatible schema refusal; auth rejection; real CLI first-run and actionable errors. Remote hosts, native GUI, tmux continuation, real ACP provider validation and full release packaging remain separate gates.

ACP startup cancellation does not bind established processes to a browser connection. Shutdown cancels pending handshakes and stops managed process groups. ACP exit is recorded after its stdout reader drains; an abnormal read failure marks capture degraded. The two-second post-exit pipe-read deadline bounds descendants that retain stdout, rather than declaring missing frames complete.

## Experimental terminal extension

`open --terminal screen-v1` opts into a server-owned terminal engine, full-frame `screen` reads and TTY-only `attach`. The default raw profile retains legacy compatibility. Interactive control holds a private in-memory lease, renews it every 20 seconds, and uses base64 input to preserve arbitrary byte boundaries. Standalone `input` remains UTF-8. `renew` extends valid existing control without rotating its token. Explicit takeover still fences it.

Ctrl-] cancels attachment; terminal input/output flags and raw mode are restored after the input reader joins. Slow output is bounded and cancellable. Uncertain input delivery terminates attachment without replaying it. Observer attachment never acquires, renews, resizes or sends input. Both roles reconnect from complete current frames rather than executing recorded escape sequences. A child exit leaves a final frame accessible with `screen` and returns the child's exit status from `attach`.

Live frames are volatile and bounded; a block opened with `--recording visible` additionally keeps its last committed frame for post-exit/restart reads. The unchanged browser cannot attach to screen-v1. Interactive input and renewals pass through the operation ledger, whose 4096-identity window retires older resolved requests; this is an experimental local milestone, not an indefinite production terminal session. [Terminal API](terminal-screen-api.md) and [engine limits](terminal-engine.md) define the narrower contract.

Interactive viewers require at least 40 columns by 3 rows. TERM=dumb returns unsupported before control acquisition or raw mode. NO_COLOR selects monochrome application rows for that viewer; control sequences and status contrast remain necessary. Ctrl-] prints a state-aware reconnect command after restoration.
