# Sources and interpretation

> **Lifecycle:** living — reviewed 2026-09-09. External claims below are separate from project recommendations.

## Superlogical

Source: https://www.superlogical.com/

The stated direction is a durable session layer across interactive, automatic, and production work, beginning with a terminal multiplexer, then composition, then production operation. Web and native clients and shared sessions are part of the plan. This is a stated roadmap, not evidence that every stage is already delivered.

**Our interpretation:** a useful session should survive its viewer and expose structured operations. Continuum adopts that design objective, without claiming compatibility with an unpublished Superlogical protocol.

## Mitchell Hashimoto's remote-session demo

Source: https://x.com/mitchellh/status/2097424868203758046

Reviewed the complete autogenerated caption transcript and playback samples. The video demonstrates local/remote persistent sessions, OS-login behavior, identity and OS-user mapping, CLI session creation/removal, reconnect, and local/remote directory navigation. Approximate segments: 0:30–1:30 remote login; 2:10–2:55 identity; 3:00–4:30 session management/reconnect; 4:50–5:35 directory picker. Responsiveness and Mosh-inspired behavior are presenter claims; no independent benchmark was run. The presenter explicitly withholds some transport/architecture details.

**Our interpretation:** remote directory operations and an explicit identity model matter as much as opening a remote terminal. Include them as scoped milestones, without inferring unrevealed implementation details or asserting SSH-replacement parity today.

## Nushell interleave

Source: https://www.nushell.sh/commands/docs/interleave.html

The command reads streams concurrently and yields available items. Source order is preserved; cross-source ordering is unspecified. Buffering is configurable. Round-robin behavior is a different composition.

**Our interpretation:** expose source-labelled structured events that can be merged and processed independently of a UI. Completion waits do not substitute for output streams.

## Go concurrency

Source: https://go.dev/doc/effective_go#concurrency

Go provides goroutines and channels for concurrent work. This fits stream consumers and session workers. The more important project-specific reason is reuse of the existing tested Go relay. This is an engineering recommendation, not a Go-versus-Rust performance result. The Effective Go document is historical guidance, not a current dependency/version selection source.

## Terminal/session source research — 2026-09-09

Cloned and inspected tmax, Ghostex, stacks2099 and its successor ptyZZZ, including the stacks journey and Ghostex's pinned zmx persistence dependency. The [release-planning crib sheet](research/terminal-session-crib-sheet-2026-09-09.md) separates code observations, author reports and recommendations; the [source manifest](research/terminal-session-sources-2026-09-09.json) pins revisions and local clones.

The principal recommendation is to evaluate server-owned terminal state and query handling before broadening remote/client scope. Keep the Go runtime, test a bounded terminal-engine interface, and distinguish screen reconstruction from retained output and process survival. These are planning inputs; no runtime change or release commitment is implied. Upstream application tests and benchmarks were not run.
